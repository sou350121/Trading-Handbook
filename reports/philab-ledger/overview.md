# philab 帳本

> `reports/deep-research/` 是對單一問題的對抗式深挖，`reports/trading-daily/` 是每日
> arxiv 掃描。**這一區是第三種**：一台自動化研究迴圈的**連續裁決流**——
> 每 2 天一期，報告它問了哪些投資哲學主張、量到多少、**偵測下限在哪**、
> 以及本期推翻了自己的哪些說法。

**Status:** v0.1 — 自動產出（`scripts/autoresearch/philab/publish.py`），
Opus 設計格式與防護欄。每期由系統自己的裁決檔、閘門紀錄與 git log 生成，
**不經人手改寫**。

## 先講最重要的一句

**站得住的發現：0。**

自系統啟用至今 45 條主張級裁決，沒有一條晉級成「站得住」，
19 條因主張原文在一次重抽事故中佚失而**永久不可稽核**，
封存窗（holdout）**一次都沒有動用過**。

這不是謙虛，是現況。**這一區出版的不是投資發現**——寫成那樣是騙人，
而且有人會拿去交易。它出版的是三樣「發現」以外的東西：

| 出版什麼 | 為什麼它比「發現」更耐放 |
|---|---|
| **操作化過程** | 一句哲學怎麼變成可測的陳述——**以及哪些變不出來、為什麼**。文獻只寫成功的那一半 |
| **有界的否定** | 「沒偵測到，而本儀器的下限是 0.024」≠「無效」。多數負結果沒有下限，所以讀不出資訊 |
| **儀器自己的極限** | 偵測下限、覆蓋分母、燒痕、已知的汙染。**沒有正對照的管線，它的「沒發現」讀不出資訊** |

外加一樣可能最可轉移的：**故障分類學**——機器故障偽裝成科學結論的實例。
任何人做自動化研究都會撞到那些形狀，而它們幾乎不會被寫進論文。

## 怎麼讀一期

每期三個區塊，逐條裁決一張卡片：

```
主張原文（逐字）          ← 離開原文的裁決無法被稽核
怎麼被量的                ← 操作化為什麼規格、量到多少、下限多少、死在哪道閘
本裁決不主張什麼          ← **機器填的**，從該裁決自己的欄位推出來
機器可讀紀錄（JSON）      ← agent 直接解析
```

「本裁決不主張什麼」是本區最該被抄走的設計。它不是免責聲明，是**從資料算出來的邊界**——
例如當偵測下限是 0.024 時它會自己寫「不主張效果為零，小於 0.024 的東西這裡看不見」。
它存在的唯一理由，是擋住那句最常見的誤讀：**「REFUTED ⇒ 那位投資人錯了」**。

## 給 agent

機器真相在 [`data/philab/verdicts.jsonl`](https://github.com/sou350121/Trading-Handbook/blob/main/data/philab/verdicts.jsonl)，
一行一條裁決卡片。引用前**必須**檢查三個布林欄位：

| 欄位 | `false` / `true` 時的意思 |
|---|---|
| `auditable: false` | 主張原文已佚——**這條裁決無法被稽核，不得引用為證據** |
| `represents_claim: false` | 過閘的規格量錯了東西——**數字是真的，但它不是這條主張的數字** |
| `contaminated: true` | 該輪有已知的機器故障，`contamination_note` 寫明是什麼 |

另外三個欄位決定一個負結果能讀多重：
`detection_floor`（小於它看不見）、`coverage`（分母完不完整）、
`power_status`（`no_calibration_for_mode` ⇒ 空結果只能讀成「沒看到」）。

**沒有任何一期含建議、訊號或部位。** `epistemic_status` 恆為 `EXPLORATORY`：
探索期產出不計入多重性分母，要成為結論必須另寫確認 protocol 並花封存窗，
而那是人的決定。
