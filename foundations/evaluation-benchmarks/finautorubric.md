# FinAutoRubric 解構（FinAutoRubric）

> **導讀發布**：2026-10-01 · （無 venue）
> **QuantML 導讀**：[华尔街顶级阵容联手：如何评测金融大模型](https://mp.weixin.qq.com/s?__biz=Mzg2MzAwNzM0NQ==&mid=2247494631&idx=1&sn=152d44ad3cab96a2a66d7167c6500410&chksm=ce7d8cf9f90a05ef0d10de213cbd39fe540cabd5c4a7c17f6e367d0e17e12666ce50366253b6#rd)

**Status:** v0.5 — 基於 QuantML 導讀（有原文則以原文為準）。細節待升 v1。
**TL;DR:** FinAutoRubric 把金融研究智能體的評分細則生成拆成三件事：專家只維護 10 條原則與 200 個任務模板，代碼凍結 100 分預算，GPT 系撰寫智能體在截止日前檢索並用 Python 復算，Claude 系審核智能體在無網沙盒逐項推翻。核心 trick 不是讓模型更會打分，而是用異構模型交叉驗算與八條代碼門禁把 rubric 變成可審計產物。對「多智能體博弈 × 人機協同可解釋」這條軸★，它把人類從逐題編寫移到原則層，並留下證據鏈。關鍵實證：BigFinanceBench 數值考核點覆蓋率 60.8% 對比未具名直接生成基線 32.5%；與人類專家排名相關性 0.616。

**X-Ray.** 放回五軸 Pareto，FinAutoRubric 不是新的 alpha 模型，而是把「評測」變成可審計的生成式管線：以多智能體博弈（撰寫 vs 無網復算）換取數值錨定，以人類原則庫保留可解釋性。它解掉舊工程坑——人工逐題寫標準、資料凍結、只列維度不落數值；但 envelope 也很清楚：每題數千秒與專有數據接口成本、截止日／沙盒若失效即泄漏、100 題新基準不足以證明跨資產完備。對量化讀者，價值在於用可追溯 rubric 驗收 LLM 研究員，而不是把 0.616 當成 alpha 或取代人類。

## §1 · 架構 / Core Mechanism

### 1.1 三大改動 vs 前作

| 維度 | 前作（TICK／RocketEval／Qworld 等） | FinAutoRubric |
|---|---|---|
| 專家角色 | 逐題撰寫標準答案或維度清單 | 只維護 10 條抽象原則與 200 個任務模板，分值由代碼凍結 |
| 評分細則 | 基於提問或網頁初篩列考核清單，常缺數值錨定 | 撰寫智能體在截止日前檢索、跑 Python、提交證據／參考解答／任務契約 |
| 驗證 | 單模型自評或無獨立復算 | 異構審核智能體在無網沙盒逐項復算，宏觀八條代碼門禁 |

### 1.2 ⚡ Eureka

一句話：把 rubric 當可審計的編譯產物——專家給原則，代碼給預算，異構模型互相推翻。

直覺：評分標準的瓶頸不是「寫得多」，而是每個數字有出處、每個公式能被另一個模型家族的代碼獨立復算；覆蓋率清單再漂亮，沒有數值錨定就分不清嚴謹計算與編造。

### 1.3 信息流 ASCII 圖

```text
專家原則庫(10) + 任務模板(200) + 原子標準(1224)
                 │
問題 ──> 分解智能體（無檢索）──> 任務簽名 + 8 類參數 + 截止日
                 │
        代碼編排：100 分預算凍結 + 義務項配額
                 │
撰寫智能體 GPT-5.6 Sol（聯網 + Python）
   └─ 證據記錄 / 參考解答 / 任務契約
                 │
審核智能體 Claude Opus 5（無網容器）
   └─ 逐項復算、核對小數取舍、推翻不合規項
                 │
        八條代碼門禁（結論分值占比、步驟分行、二元判斷、新會話重審）
                 │
   通過 ──> 帶數值錨定與容差的評分細則
   連續失敗 ──> 阻斷並報警人工專家
```

## §2 · 數學層

📌 **Napkin Formula**（導讀未披露原論文目標函數／損失；以下為流程約束的符號化，非原文方程）：

\[
\sum_i s_i = 100,\quad s_i \text{ 由編排代碼在模型動筆前凍結}
\]

\[
R_j = \operatorname{Recompute}(evidence_j) \in \{\text{pass}, \text{fail}\}
\]

複雜度：未披露；導讀只說每題需數千秒、多輪工具檢索與長程校驗。直覺：這不是訓練一個新打分模型，而是用代碼約束打分空間，再用異構模型把每個數值錨點壓到可復算。Loss／訓練細節：非訓練式方法，無 loss；預訓練截止日、tokenizer 版本、適配／微調時間、topic 擬合時間均未披露，不能把模型預訓練截止日套成評測資訊截止日。

## §2.5 · 帶數字走一遍（Worked Example）

以下為示意，非論文實證；只借用導讀逐字常數，不補任何未披露比率。

1. 專家庫：10 條原則 → 200 個任務模板 → 1224 條原子級考核標準（導讀數字）。
2. 輸入問題，分解智能體在無檢索下輸出任務簽名、8 類參數與截止日。
3. 編排代碼把 100 分總預算按義務項凍結；設義務項數為 n（示意變數，不代入新值），每項配額 \(s_i=100/n\)。
4. 撰寫智能體在截止日前檢索公告／財報，對每個數值提交 evidence link、Python 復算與容差 tol（示意變數）。
5. 審核智能體在無網容器重算 \(v_{calc}\)；若 \(|v_{calc}-v_{ref}|\le tol\) 則 pass，否則 fail；連續 fail 觸發阻斷／人工報警。
6. 八條代碼門禁檢查結論分值占比超過一半、計算步驟分行、二元判斷、結構修改新會話重審；輸出 rubric。

## §3 · 數據層

- **任務庫**：10 條核心原則、200 個抽象任務模板、1224 條原子級考核標準；專家只在頂層對 200 個模板做一次性把關。
- **評測集**：BigFinanceBench、FrontierFinance、Finance Agent Benchmark；新建 FinAutoRubric Benchmark 100 題、78 種細分任務類型、橫跨八大領域，公募權益題目僅占一半。
- **頻率／時段**：跨多個財報周期；資訊截止日由代碼鎖定，具體日期未披露；取樣頻率未披露。
- **來源**：真實公告與財報、檢索與 Python 計算；審核端只能訪問撰寫者提交的原始出處連結，運行在獨立無網容器。
- **樣本外與容量**：未披露；不能判定 survivorship；輔助數據缺失不是生存者偏差，但若只納入可取得申報文件，樣本選擇是否偏誤仍待原論文核對。
- **時間邊界分列**：預訓練截止日—未披露；tokenizer 版本／時間—未披露；適配／微調時間—未披露；topic 擬合時間—未披露；評測資訊截止日—未披露（只知由代碼鎖定）。不可把預訓練截止日套到適配後權重或評測截止日。

## §5 · 評測 / Benchmark

| 數據集/市場 | Metric | 前SOTA | 本方法 | Δ |
|---|---|---|---|---|
| BigFinanceBench | 帶具體數值考核點覆蓋率 | 未具名直接生成基線 32.5% | 60.8% | +28.3pp |
| Finance Agent Benchmark | 帶具體數值考核點覆蓋率 | 未具名直接生成基線 46.4% | 80.8% | +34.4pp |

導讀另稱 TICK／RocketEval 落在 13% 到 28% 的低位；因未逐一給出可對應的單一基線值，不合成「前 SOTA 區間」。

排名相關性：FinAutoRubric 在 BigFinanceBench 與人類專家打分排名相關性 0.616；導讀稱其他自動生成基線普遍在 0.42 到 0.52，未逐一具名，故不合成單一 SOTA、不計算 Δ。平均絕對分差：基線 26 到 31 個百分點，本方法 19.0 個百分點；基線為區間，不計算 Δ。Qworld 維度覆蓋率超過九成，但排序相關性只有 0.34 到 0.54，說明「覆蓋維度」不等於「數值錨定能力」。

盲審：45 道題中，有效判決裡 79% 選擇 FinAutoRubric，16% 選擇專家手寫原版；其餘未披露。導讀列舉 Shake Shack、Intel、Tesla 三處專家原題事實錯誤，削弱「人類原版即 gold」的假設，但不證明自動 rubric 全面優於人類。

FinAutoRubric Benchmark 上，六款模型（GPT-6 Astra、Fable 5.1、Muse Spark 1.3、DeepSeek V4.1-Flash、Gemini 3.8 Flash、GLM-5.3）被分層；GPT-6 Astra 在定量計算、事實檢索、綜合判斷、論據支持四維均第一，綜合得分 77.3 分，但距滿分差距數值未披露。

解讀：數值覆蓋率的 Δ 更像「管線 capability」——強制證據、代碼復算與異構審核把 rubric 壓向可核對數字；但它不直接等於推理能力。0.616 的排名相關性只是中等，19.0 個百分點的絕對分差仍大；盲審偏好是「分析師更願意用」，不是客觀正確率。若截止日或無網沙盒失效，覆蓋率可能被前瞻資訊灌水；成本與延遲未進入上述 metric。

## §6 · 失效與隱含假設

### 6.1 論文自述 limitations

僅讀 QuantML 導讀，**原論文作者限制未核**；以下只列導讀明示的工程代價，不能把導讀未見當成論文沒有，圖表／附件待核。

- 每題需數千秒、多輪高推理模型與工具檢索，計算耗時與 API 成本顯著高於單次大模型調用的朴素基線。
- 對底層算力與專有金融數據庫接口穩定性要求極高。
- 跨資產泛化只由 100 題新基準支撐；更多市場、更多財報週期未見。
- 導讀未給部署樣本量、breakeven 成本、失效閾值；本頁不補。

### 6.2 推斷的隱含假設（明標推斷）

- **截止日可強制執行**：若無網沙盒或截止日隔離失效，撰寫／審核智能體可能看到未來資料，數值覆蓋率與相關性會被泄漏推高。
- **異構模型真的獨立**：假設 GPT 系與 Claude 系不共享足夠盲區；若換成同家族模型，交叉驗算可能退化。
- **原則庫覆蓋足夠**：10 條原則、200 個模板、1224 條原子標準被假設能覆蓋長尾會計例外；導讀未給覆蓋率統計。
- **代碼預算能替代專家權重**：100 分凍結與八條門禁被假設不會壓縮特殊財報語境下的關鍵變量。
- **參考數值可復算**：假設公開申報在截止日前足以推出參考值；私有數據、歷史重述、併購口徑可能使復算失效。
- **成本可被接受**：假設嚴肅合規／研究場景願付每題數千秒；未見容量與延遲邊界。
- **樣本選擇**：導讀未披露題目篩選；不能判定 survivorship，也不能把輔助數據缺失直接說成生存者偏差。

| 同軸對手 | 關鍵差異軸 | Open? | Status |

| 人類專家原版 rubric | 人工逐題、靜態、易有抄寫與口徑錯誤 | 未披露 | 盲審中 16% 被選 |

🎤 **Interview Tip**
- **正確答**：FinAutoRubric 的貢獻是把 rubric 生成變成可審計流水線——專家只給原則、代碼凍結 100 分預算、GPT 系起草、Claude 系在無網沙盒逐項復算；異構性與截止日約束是核心。評測顯示數值覆蓋率提升，但排名相關性 0.616 只是中等，且成本高。
- **錯答**：「又一個 LLM-as-judge，換更強模型寫 rubric 就贏」或「0.616 等於取代人類專家」。忽略異構審核、代碼門禁、截止日與成本，等於把管線能力誤讀成單模型能力。

### 7.1 可證偽預測帶日期

- 到 2027-06-30：若把審核端換成同家族模型，導讀所述數值覆蓋率優勢應縮小或審核推翻率下降；若無變化，異構性假設被削弱。
- 到 2027-12-31：獨立團隊在更新截止日後重跑，若未嚴格無網／截止日隔離，數值覆蓋率與專家排名相關性應顯著下降；若仍維持，泄漏風險較低。
- 到 2027-12-31：若每題成本不降，該流程在低延遲生產場景的採用率應低於合規／研究場景。

## §8 · For the Reader

- **因子研究員**：把它當 LLM 研究備忘錄的驗收器，重點看數值錨定、容差與截止日；不要把它當 alpha 信號或收益預測器。
- **高頻執行**：不適合在線低延遲決策；每題數千秒只適合盤後研究、合規與模型驗收。
- **組合配置**：可用來做管理人／研究智能體的 due diligence，但保留人類簽核；盲審偏好 79% 不是客觀正確率。
- **LLM-agent 研究者**：優先復現「異構審核 + 代碼凍結預算 + 無網沙盒」三件套，並做同家族 vs 異家族消融；注意截止日泄漏。
- **RL 策略**：若拿 rubric 當 reward model，先驗證數值覆蓋與可遊戲性；導讀沒有 reward hacking 實驗。
- **研究學生**：讀方法論而不是只讀分數；把 10／200／1224 的設計、八條門禁、成本曲線當成可拆解的研究對象。
