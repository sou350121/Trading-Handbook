## §1 · 架构 / Core Mechanism

### 1.1 常见做法 vs 本文案例做法

| 维度 | 常见做法（对照） | 本文案例做法 | 差异与边界 |
|---|---|---|---|
| 验证基准 | 全周期夏普、收益最大回撤比、胜率 | 单笔成交与离线重放的盈亏容差对账 | 来源案例中，聚合指标未暴露符号相反的实现错误；单笔对账用于定位实现分歧，但不保证充分 |
| 一致性保障 | 默认回测与实盘共用数据 / 时钟 / 配置 | 自动化用例断言原始价格、单一全局时区函数、配置键双向绑定 | 分歧可能只在实盘暴露，回测永远自洽；这是来源案例的限制描述 |
| 风控约束位置 | 写在流程开头卡一次 | 最具约束力的限制移到链条末端、每次规模放大后重应用 | 来源案例中，开头卡一次后被下游放大系数穿透；末端重校验/每次放大后重应用是条件性的必要防护之一，不证明对所有系统充分 |

### 1.2 ⚡ Eureka

> **把检验粒度从“日 / 周级统计量”压到“单笔盈亏”，且重放必须复用实盘同一份策略入口代码与当时抓取的分笔快照。**

直觉：统计量是聚合函数，在来源案例中会掩盖彼此抵消的实现错误；单笔对账提高定位能力，但**不等于错误无处可藏**。第二层 eureka 更反直觉——**选股决策一致只是及格线**：作者维护的简化脚本在大部分实盘日期做出相同开仓决定，但因离线推导特征时读错数据，跑出来的总利润“连主系统的一半都不到”。“选股决策对上了，数字依然是错的。”

## §2 · 数学层

📌 **Napkin Formula**

```
∀ i ∈ trades :  | PnL_live,i − PnL_replay,i | ≤ ε          (逐笔容差判据)
q_final = min( q_scaled , Q_purchasing_power )             (末端硬顶，每次放大后重算)
```

复杂度 `O(N_trades)`，随标的数 × 交易日数线性；**无参数拟合**，`ε` 的具体数值导读未给（全文未读，不能断言论文未披露）。此式是对来源工程准则的摘要，非来源给出的数学训练模型。

直觉：常规回测最小化的是期望误差，这里约束的是逐笔容差 gate。来源案例显示聚合指标未暴露抵消错误；但不能把它推广为“前者一定放过、后者一个都不放过”。代价是它没有可优化的梯度——**它是 gate，不是 objective**。

Loss / 训练细节：无训练、无损失函数、无超参搜索（导读未给；全文未读，不能断言论文未披露）。十项防线清单是工程准则，不是可微目标。

## §2.5 · 带数字走一遍（Worked Example）

> ⚠️ **以下全部为假设 / 示意数值，用于演示机制，非论文实证结果。** 论文的真实数字一律留在 §5；§5 缺失者写“导读未给”。

1. **示意输入**：某日账户在购买力约束下允许的最大股数 `Q_bp = 100` 股。
2. **策略侧**：单笔上限 `80` 股，下游有一个风险敞口放大系数 `2×`。
3. **无末端校验的链路**：`min(80, 100) = 80` → `80 × 2 = 160` 股 > `100`，**穿透**真实账户承载能力。（对应原文：放大系数把已卡在购买力上限的头寸再次乘法放大，后面没有任何二次校验拦截。）
4. **有末端校验**：`min(160, 100) = 100` 股，合规。差别只在“硬顶放在链条哪一端”。
5. **反向对冲（关键）**：若辅助标的缺失被静默填零，特征得分被压低，初算规模掉到 `40` 股 → `40 × 2 = 80` 股 ≤ `100`，**不触发穿透**，对账竟然“通过”。一个 bug 放大了仓位，另一个 bug 压小了信号，两相抵消。
6. **结论**：第 5 步说明对账通过不是正确性证明。只有先彻底修好数据缺失，第 4 步那个仓位漏洞才会重新暴露出来。

可引的定量**全部是工程审计计数**，衡量缺陷规模而非策略优劣：

- “六十多笔”成交里有“二十笔”交易头寸规模远超实盘账户极限，回测报告资金占用虚高“近两成”；
- “超过三分之一”的标的发生了价格偏移，偏移幅度在“百分之零点六八到百分之一点六五”之间，无一例外全是分红股票；
- 生产代码实际读取“五十三项”未在配置文件中显式声明的隐藏参数，占到了整个系统参数面的“四分之一”；
- 冬令时抽样中“百分之十六”的股票在盘前冷门 K 线上被强行打分，“百分之八十四”因数据完整性校验未通过被静默丢弃；
- 辅助数据缺失导致重放建立在错误特征基准上的时间达“四个月”；
- 某项缩放规则在实盘“十多天”的运行中完全是僵尸代码。

这些数字不能被读成“策略能赚多少”，只能读成“在该来源案例中，缺陷能藏多深”；不能推论所有系统都会出现同样规模或同样隐蔽的缺陷。

🎤 **Interview Tip**

- **问**：回测夏普正常、实盘衰减，你的排查顺序？
- ✗ **只做一阶统计校正**：先上 deflated Sharpe / 多重检验校正，直接怀疑因子过拟合。→ 在来源案例中，这会漏掉数据、时钟与配置链路；这不是说统计校正无价值，而是排查顺序不应把它当第一步。

### 7.1 可用重放测试反证的條件性命題（檢查期限：2027-06-30，僅本手冊複核期限）

以下**不是來源預測**，也不是對市場的預測；只是把來源案例中的機制寫成條件式可測命題，需以相同數據口徑重放檢驗。

- **P1（券商接口默認參數）**：對來源所涉券商接口，若歷史行情請求未顯式指定數據源參數、而實盤實時請求取全市場統一盤口，則用同一天開盤首分鐘做重放對賬，可檢查歷史緩存首分鐘成交量是否相對實盤偏低。若在相同參數與口徑下未見偏低，則該命題在該接口/配置被反證。
- **P2（多步倉位鏈）**：若購買力硬頂只在倉位鏈開頭施加、下游存在放大係數且無末端重校驗，則用同一訂單重放，可檢查最終股數是否超過購買力上限。若未超過，或超限不由該結構導致，則該命題被反證；有放大係數但無末端校驗，不保證一定超限。
- **P3（跨夏令時靜態時間戳）**：對寫死“十三點三十分”UTC 的掃描腳本，用冬令時樣本日重放，可檢查被丟棄樣本的時間分布是否集中於盤前/非目標時段。若丟棄分布與目標時段無差異，則該命題在此樣本被反證。

**反證條件**：若在相同接口、配置與數據口徑下重放，未觀察到上述不一致，則相應命題在該案例被反證；若某系統已顯式做齊上述三項斷言、仍出現單筆對賬不一致，則說明來源六類分類在該案例外仍有未涵蓋缺陷（不是對論文全文的判決）。

## §8 · For the Reader

- **因子研究员**：如果你的 alpha 建在开盘几分钟的微观结构上，先把数据源默认参数与复权口径核到逐笔，再谈显著性。导读中“九十多个交易日”里每日都有标的的开盘量被稀释到零头，而这在日频总量校验里不留痕迹——你的因子可能从输入端就已经是另一个东西。
- **高频执行**：原始价格用于撮合、调整价格用于研究，这两条线要工程上隔离，不是靠注释或参数命名区分。一次“由仅拆股改为全部调整”的提交就足以让撮合基准与交易所订单簿脱节。
- **组合配置**：在来源案例的仓位链条中，若购买力 / 保证金硬顶只在流程开头卡一次、下游又会放大且无末端重校验，则可能穿透。因此在该类链条中，末端重校验或每次放大后重应用硬顶是**必要防护之一**；是否充分取决于其他约束。不能说“写在流程开头等于没写”，只能说在来源案例的该结构下不足。
- **RL 策略 / LLM-agent（类比）**：静默填零可类比为 reward hacking 的数据版——缺失输入应停机。任何“优雅回退到中性默认值”的兜底，都可能把工程错误转译成训练信号或决策信号（此为类比推断，非来源结论）。
- **研究学生**：这是一篇负结果工程学范文。学它怎么把一次 bug 复盘写成**可执行断言**，而不是写成运维笔记——作者团队曾把时区规范写进笔记，几个月后同一个错误照样卷土重来。“代码永远比文字记忆诚实。”
