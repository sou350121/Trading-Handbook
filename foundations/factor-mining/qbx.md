# QBX 解構（QBX）

> **導讀發布**：2026-11-02 · ICAIF'26
> **QuantML 導讀**：[QBX：一个编译器，因子有效率从27%跃升至98%](https://mp.weixin.qq.com/s?__biz=Mzg2MzAwNzM0NQ==&mid=2247494792&idx=1&sn=7823c9b754a1a27cf5ea468f705883d8&chksm=ce7d8b96f90a02801a62bab267eefb1fa93ad07edc267de103b5423f22f243a019575d650dbc#rd)
> **核心定位**：五軸落在「量價表格 × 日頻波段 × 元學習搜索 × 因子挖掘 × 人機協同可解釋」；解的是生成器各自拼流水線、語法／型別／前視錯誤要到回測才暴露、試驗次數無賬本的 prior gap——把合法性與審計做成編譯期底座。

**Status:** v0.5 — 基於 QuantML 導讀（有原文則以原文為準）。細節待升 v1；原論文作者限制未核。
**TL;DR:** ① QBX 把因子／策略從自由文本改成帶型別簽名的端口有向圖，在回測前做靜態型別與時序檢查，並用兩級 Merkle 哈希同時做增量復用與試驗賬本。② 核心 trick 是把「未來函數」編碼成節點時序偏移量、跨節點取最晚到達者，偏移量轉正即拒——零行情加載下單次檢查僅幾十微秒。③ 對「元學習搜索 × 因子挖掘」軸★：它把搜索的合法性與審計從生成器裡拆出來，讓 LLM／GA／人共用同一准入與記賬口徑。④ 關鍵實證：A 股日頻 300 輪等預算對比，自由文本有效率 26.8%、僅語法 36.4%、QBX 97.7%；但純編譯器搜索多樣性塌陷（廣度 1.0 到 1.9），需 LLM 廣度補位。

**X-Ray.** 放回五軸 Pareto，這是「元學習搜索 × 因子挖掘」軸上的基礎設施工作，不是新 alpha。它解的舊工程坑很具體：生成器輸出直接進回測，回測崩潰兼任語法檢查器；同一數學邏輯換變量名就重複回測；冠軍因子是在未知次數試驗裡挑出來的最大值，多重檢驗沒有可信分母。QBX 的論斷價值在於把「合法性」與「審計」提升為編譯期不變量，這比再多一個生成器更有複用性。預測它打不開的 envelope：註冊表封閉（95 個算子模塊／261 個端口）決定表達上限；時序偏移模型對非規則採樣、事件驅動、跨頻對齊的覆蓋未核；根哈希去重只保證結構身份，不保證統計獨立，多重檢驗分母仍可能偏樂觀。對量化讀者的意義：這是把因子挖掘從「腳本＋回測」推向「CI＋賬本」的範式，但收益提升不是它證明的——導讀自己也說純編譯器會模式收縮。實盤成本、容量、樣本外時段所讀文本未見，別把准入率當 alpha 率。

## §1 · 架構 / Core Mechanism

### 1.1 · 三大改動 vs 前作

| 維度 | 傳統／前作做法 | QBX 改動 |
|---|---|---|
| 策略表示 | 自由文本字符串直接丟進回測引擎 | 型別化端口有向無環圖：95 個版本受控算子模塊、261 個具名端口、10 個基本原子型別建出 13 種型別表達式；含 25 種技術指標、13 種時序變換、12 種基本算子、7 套執行模型、4 套頭寸管理 |
| 合法性檢查 | 回測崩潰或異常收益後回頭排查；無獨立校驗層 | 編譯期靜態型別＋時序效果檢查，不載入行情，單次檢查幾十微秒 |
| 計算與審計 | 每次全量回測；無試驗次數賬本 | 兩級 Merkle 哈希：節點哈希做增量復用，根哈希做試驗賬本鍵 |

### 1.2 · ⚡ Eureka

一句話：**把「未來函數」變成一個帶符號整數**——每個節點在邏輯時間軸上有偏移量，跨節點聚合取最晚到達的輸入支路，只要結果偏移量轉正，整個編譯立即中斷。

直覺：前視洩露不是數值精度問題，是時間可達性問題；用 max 聚合等價於求偏序的上界，所以不需要載入任何市場數據就能判定「這個節點在當前截面不可能算出來」。這使前視從「回測才發現的異常收益」降級為「編譯期型別錯誤」。

### 1.3 · 信息流

```
生成器（LLM / GA / 人）
        │  候選策略圖（端口有向圖）
        ▼
┌─────────────────────────────┐
│ 型別檢查：端口簽名匹配        │──✗──► 結構化診斷（生成階段打回）
│ 時序效果：offset ≤ 0 ?       │──✗──► 前視洩露，編譯中斷
└─────────────────────────────┘
        │ 通過
        ▼
節點哈希 h(n) ──► 緩存查詢：只重算下游依賴錐體
        │
        ▼
根哈希 H(G) ──► 試驗賬本鍵：結構相同則合併、跳過回測
        │
        ▼
回測引擎（全量或增量）
```

## §2 · 數學層

📌 **Napkin Formula**（以下為本頁對導讀描述的形式化，非導讀逐字公式）

1. 時序准入：`offset(n) = max_{p∈parents(n)} offset(p) + shift(op_n)`，要求所有物化節點 `offset(n) ≤ 0`。
2. 節點身份：`h(n) = SHA-256( canonical(semantics_n, params_n, out_type_n, op_def_n, sort(h(parents))) )`。
3. 圖身份：`H(G) = aggregate({h(n)}_{n∈G}, compiler_version, registry_version)`。

**複雜度**：全圖靜態檢查為圖遍歷量級（本頁記為 `O(V+E)`，導讀未給複雜度式）；增量回測只重算被修改節點的下游依賴錐體。

**直覺**：第 1 式把「前視」壓縮成一個純量符號問題；第 2 式讓變量重命名與排版不影響身份；第 3 式讓「算力緩存」與「統計記賬」共用同一把鑰匙——結構沒變就不算新試驗，結構變了才算。

**Loss／訓練**：非梯度訓練，無 loss；搜索由外部生成器驅動（LLM／GA／人），編譯器只做准入與記賬。導讀未給訓練細節。

## §2.5 · 帶數字走一遍（Worked Example）

以下用導讀自己的示例「均線窗口從 20 調到 60」作**假設／示意**；數字來自導讀示例，非論文實證結果。

1. 假設父圖 `G0` 含一個 MA 節點 `n_MA`，參數 `window=20`，其上游是數據節點、下游是某個組合節點。
2. 子代 `G1` 只把 `window` 改為 `60`。由於 `params` 進入 canonical 串，`h(n_MA)` 改變。
3. 失效傳播：只有 `n_MA` 及其下游依賴錐體需要重算；上游節點哈希不變，直接命中緩存。
4. `H(G1)` 因 `h(n_MA)` 改變而改變，賬本記為一次新試驗——即使它與 `G0` 只差一個參數。
5. 反例：若只是把變量名從 `x` 改成 `y`，canonical 後 `h(n)` 不變，根哈希不變，回測前直接跳過並合併為同一次試驗。
6. 時序側：若某節點引用「後一期收盤價」，其 `offset` 轉正，編譯中斷；本例 MA 的窗口與滯後操作保持 `offset ≤ 0`，故通過。

**解讀。** 真 capability 在准入與攔截，不在收益：自由文本 26.8% 與僅語法 36.4% 對比 QBX 97.7%，是同一等預算下的准入口徑；導讀的分解稱常規語法檢查只能解釋 13.5% 的准入差距，其餘 86.5% 來自深層型別匹配與時序安全，這支持「型別＋時序是主因」而非單純語法過濾。對抗測試中常規切分回測漏檢率百分之百、靜態檢查攔截全部 6 個，這是機制性證據，不是曲線擬合。需打問號的部分：有效因子數 7／38／204 是產出計數，不等於樣本外 alpha；導讀另稱混合模式相比純大模型在測試集 RankICIR 穩定提升約 0.036 到 0.038，但切分、成本、容量未披露；增量 7.5 倍是蘋果小時級重放，不能外推日頻全鏈。成本、換手、容量導讀未給，所讀文本未見。

## §6 · 失效與隱含假設

### 6.1 · 論文自述 limitations

**原論文作者限制未核；以下僅為導讀轉述，不得把導讀未見當作論文沒有。** 導讀明說：純編譯器閉包搜索會模式收縮，選出前列策略組合的因子有效廣度只有 1.0 到 1.9，甚至兩個合成因子表現數值在小數點後四位完全相同；大模型直接生成的候選廣度達 4.6 到 9.3；因此需 LLM 宏觀廣度＋編譯器微觀深度。其他限制（樣本外衰減、成本、容量、註冊表覆蓋）導讀未展開，待核。

### 6.2 · 推斷的隱含假設（明標推斷）

1. **註冊表封閉完備性假設**：95 模塊／261 端口／10 原子型別被當作足夠表達策略空間。若真實 alpha 需要表外算子，編譯器給出的不是「不合法」而是「不可表達」。適用範圍僅限該註冊表；不是所有因子挖掘的必然結論。
2. **時序偏移可加性假設**：所有前視都能用整數偏移＋max 聚合表達。對非規則採樣、事件驅動、跨頻對齊未測試（導讀未見）；若成立，靜態檢查等價於合同級無前視；若不成立，可能漏檢經濟意義上的前視（如全樣本統計量歸一化）。
3. **哈希身份＝統計獨立假設（推斷）**：根哈希只保證結構不同才計新試驗；結構不同但高度相關的策略仍會膨脹分母，多重檢驗校正偏樂觀。
4. **生成器無關假設**：編譯器對 LLM／GA／人一視同仁；但導讀實證主要來自特定 LLM 生成器與 A 股日頻，跨生成器／市場的准入率未核。
5. **成本／容量／regime 假設**：准入率不等於淨收益；導讀未給交易成本、容量、牛熊分段。輔助數據缺失不是生存者偏差（此處無輔助數據）。
6. **樣本外假設**：導讀提測試集 RankICIR 但未給滾動／切分細節，洩漏風險未核。

🎤 **Interview Tip**
- **正確答**：QBX 的貢獻是准入與審計口徑——把型別錯誤與前視攔截做成編譯期不變量，並用根哈希給多重檢驗一個真實試驗分母。實證是 26.8%／36.4% → 97.7% 的准入率與 6 個前視因子全攔；收益層面導讀只給混合模式 vs 純大模型的 RankICIR 提升約 0.036 到 0.038，且純編譯器會模式收縮（廣度 1.0 到 1.9）。
- **錯答**：說「QBX 是一個新因子模型，樣本外 Sharpe 更高」，或把「有效率 97.7%」等同「97.7% 的因子能賺錢」——混淆准入率與 alpha 率，也忽略導讀自己承認的搜索多樣性邊界。

### 7.1 · 可證偽預測

自 2026-11-02 導讀發布起，至下一次 ICAIF 截稿前：

1. 第三方若按導讀復現，靜態時序檢查應在零行情加載下攔截全部構造的前視因子（導讀稱 6 個全攔）；若不能，offset／max 模型的描述有誤。
2. 純編譯器搜索的廣度塌陷應可重現（1.0 到 1.9）；若復現顯示接近大模型的 4.6 到 9.3，則導讀「模式收縮」結論被推翻。
3. 根哈希作分母的通縮夏普應低於未校正版本；導讀未給校正後數值（未披露），此項待核。
4. 若後續工作把註冊表擴到表外算子後准入率仍維持 97.7% 量級，則「封閉註冊表」不是必要條件；反之則支持完備性假設。

## §8 · For the Reader

- **因子研究員**：先把型別／時序檢查做成 CI，再談搜索；把註冊表當「可表達空間」而非「alpha 全集」，定期審計表外算子需求。注意 97.7% 是准入率，不是樣本外收益率。
- **高頻執行**：7.5 倍增量是蘋果小時級重放的搜索鏈場景；日內數據加載、滑點、容量導讀未披露，勿直接類推到高頻全鏈。
- **組合配置**：根哈希賬本可作多重檢驗分母的審計線索，但結構去重 ≠ 統計去重；相關性膨脹仍可能讓通縮夏普偏樂觀（推斷）。
- **LLM-agent**：導讀的實務結論是 LLM 廣度＋編譯器深度；「兩到三次大模型調用達到無約束二三十次效果」是導讀說法，需自行復核預算口徑。
- **RL 策略**：可把編譯器當 action mask／合法性層，把非法構型擋在 rollout 前；但導讀未做 RL，這是外推。
- **研究學生**：復現門檻在 95 模塊註冊表與圖編譯器；repo／checkpoint 未披露，先確認代碼可得性，再談復現 26.8%／36.4%／97.7% 的對比。
